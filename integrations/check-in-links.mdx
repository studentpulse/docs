---
title: "Check-in links"
description: "Pass segmentation context from your institution's system into a Check-in URL."
---

A Check-in link can include context such as course, study mode, campus, and semester. Your institution's learning or student information system can generate these links.

Use this method to select Check-in content or attach reporting context without asking students to enter that context in the Check-in.

## Choose the link type

Use a [permanent Group link](/integrations/groups) when the same class or course needs the correct Check-in over time:

```text
https://app.studentpulse.io/v2/g/GROUP_SLUG
```

StudentPulse resolves the assigned Check-in and adds the Group's Attributes. Copy this link from StudentPulse.

Use a direct Check-in link when you need one specific Check-in. Generated links can use `/check-in/CHECK_IN_UUID/intro` or `/feedback/CHECK_IN_UUID`, depending on the Organization's configuration. Keep the generated route.

Direct links can carry [Attribute](/integrations/attributes) context. They do not create [Participants](/integrations/participants) or save Participant memberships.

## Prerequisites

- A Check-in URL from StudentPulse.
- The segmentation IDs, locale codes, and option values agreed with StudentPulse.
- A source system that can build and encode a URL.

## How it works

1. Your system adds the agreed parameters to the Check-in URL.
2. A student opens the link.
3. StudentPulse reads the parameters and applies the Check-in context.
4. The Reply keeps the context for reporting.

## Existing question context

```text
https://app.studentpulse.io/feedback/CHECK_IN_UUID?source=core_segmentation&segments[]=SEGMENT_ID_LOCALE_OPTION
```

This format uses existing segmentation question IDs. It differs from the Attribute option format below. Replace `CHECK_IN_UUID` with your Check-in identifier. Each `segments[]` value contains three parts:

| Part | Meaning | Example |
| --- | --- | --- |
| `SEGMENT_ID` | The configured segmentation ID | `2010` |
| `LOCALE` | The locale code for the option | `en` |
| `OPTION` | The segmentation option value | `Mathematics 101` |

Separate these parts with underscores. For example, `2010_en_Mathematics 101` becomes `2010_en_Mathematics+101` when spaces are encoded as `+`.

Use a separate `segments[]` parameter for each value. Encode parameter values with your platform's URL tools.

## Example

This example adds course, study mode, campus, and semester context. The IDs are illustrative. Replace them with your own configuration.

```text
https://app.studentpulse.io/feedback/CHECK_IN_UUID?source=core_segmentation&segments%5B%5D=2010_en_Business+Administration+%28BBA%29&segments%5B%5D=2011_en_Full+Time&segments%5B%5D=2012_en_CPH&segments%5B%5D=2013_en_1st+semester
```

| Parameter value | Context |
| --- | --- |
| `2010_en_Business Administration (BBA)` | Course |
| `2011_en_Full Time` | Study mode |
| `2012_en_CPH` | Campus |
| `2013_en_1st semester` | Semester |

Keep the source value supplied by your entry flow. The example above uses `core_segmentation`. Generated Group links use `integration` by default.

## Attribute option context

Current Attribute links use `o-OPTION_ID_LOCALE_LABEL` values in `segments[]`. The `o-` prefix identifies an Attribute option. `OPTION_ID` is its StudentPulse ID. It is not a Group ID or an external source-system ID.

For example, a synthetic campus option could appear as:

```text
segments[]=o-33_en_north
```

Group link resolution builds these values from the Group's stored Attributes. Use generated links and agreed mappings rather than replacing the IDs yourself. Preserve a separate `segments[]` entry for each value.

A configured institution integration can also receive a keyed Attribute payload. See [Attributes](/integrations/attributes) for keys and [Groups](/integrations/groups) for matching rules. A keyed payload is not a set of arbitrary URL parameters.

## Use context in reports

Agree the mapping with StudentPulse before you generate links. Do not assume that arbitrary query parameters become export fields.

Ask StudentPulse to confirm any additional identifier that you need to join Replies to institution data. See [data exports](/exports/overview).

<Warning>
  Do not put names, email addresses, phone numbers, API keys, or other sensitive values in a Check-in URL. URLs can appear in browser history and logs. Confirm the handling of any student identifier before you use it.
</Warning>
