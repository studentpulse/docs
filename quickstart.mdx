Choose the method that matches your task. Check-in links pass context into StudentPulse. Data exports send feedback data to your reporting tools.

## Prerequisites

- Access to the target Organization in StudentPulse.
- A description of the data you need to send or receive.
- A contact who can configure your institution's source system or reporting tool.

## Get started

| Your task | Method | What to prepare |
| --- | --- | --- |
| Route students to the active Check-in for their unit | [Groups](/integrations/groups) | Stable Group IDs, Group data, and Check-in assignments |
| Describe students and their study context | [Attributes](/integrations/attributes) | Category keys, labels, and source IDs |
| Add individual contact records and memberships | [Participants](/integrations/participants) | Administrator access and a validated Participant CSV |
| Add context before a student opens a Check-in | [URL parameters](/integrations/check-in-links) | A Check-in URL and the agreed segmentation keys and values |
| Analyze feedback with institution data | [Data export](/exports/overview) | Export access for the target Organization and an agreed data mapping |
| Build a Power BI report | [Power BI and Fabric](/exports/power-bi) | Power BI Desktop, an export URL, and access to a Fabric workspace |

## Confirm the data mapping

For Check-in links, agree which values represent a course, campus, semester, or other reporting category. Your source system can then generate the links.

For exports, agree which identifiers connect the feedback data to your institution's data. Ask StudentPulse about any additional identifier you need.

## Test with example data

1. Use a test Check-in and synthetic data.
2. Open a generated link and confirm the intended Check-in context.
3. Submit a test Reply.
4. After the export refresh, confirm that your reporting tool receives the expected context.

Group and Participant imports are separate operations. Prepare existing Groups and Attribute values before importing Participant memberships.

For a source-system login flow, agree how student context reaches StudentPulse. A permanent Group link does not require a Participant record. Confirm the configured entry flow with your StudentPulse contact.
